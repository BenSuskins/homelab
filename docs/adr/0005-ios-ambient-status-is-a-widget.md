# On iOS, ambient status is a widget, not a notification

The menu bar app answers "do I need to open this?" without being opened: the Glyph State sits in the menu bar, and `FailureNotifier` posts a local notification the moment a run newly reaches a failed conclusion. Both work because the app is always running. The obvious port is to keep `FailureNotifier` — it uses `UserNotifications`, which compiles on iOS — and the obvious port is wrong. iOS suspends a backgrounded app within seconds, `AppState`'s polling loop stops with it, and `FailureDetector` never sees the failure. The notification would arrive only while the app was already open and on screen, which is the one moment it carries no information.

Decided: the iOS equivalent of the Glyph State is a **WidgetKit widget**, and `FailureNotifier` is not wired up in the iOS target at all. The widget renders `MenuSnapshot.glyph` and the worst Run Row's `subtitle(now:)` — both already pure functions of the cached Snapshot — refreshing on a timeline and falling back to the App Group cache when a fetch fails. It is an ambient indicator you read without opening anything, which is what the menu bar glyph is, rather than an interruption, which is what the notification is.

**The cost is that nothing pushes.** A widget timeline requests a refresh interval and iOS treats the request as a hint, budgeting it against battery, usage patterns and the current power state; a fifteen-minute request can be honoured at fifteen minutes or at several hours. So the widget must never be described, in the app or in the docs, as a way of finding out that a deploy failed. It tells you what was true the last time iOS let it look. Anything time-critical still comes from the macOS app, which is running on a machine that is plugged in.

`BGAppRefreshTask` was rejected for the same reason in a worse form: it is opportunistic, less predictable than a widget timeline, and it would produce a notification whose lateness is invisible — a "Terraform failed" alert two hours after the fact reads as current. Real push was rejected on cost, not on merit: GitHub cannot talk to APNs, so it needs a webhook receiver container in the lab, a public endpoint for GitHub to reach it, and an APNs auth key — a service to run, secure and back up. That is a project of its own, and it should be started only after the widget has been lived with and found insufficient, so that it is built against a known gap rather than an assumed one.
